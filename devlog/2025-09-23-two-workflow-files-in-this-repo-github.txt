⏺ Looking at the workflows, I can see the problem:

  Issue with deploy-environments.yml (lines 33-45):
  - It tries to preserve existing content by fetching the gh-pages branch
  - But it excludes the development directory when copying: find . -maxdepth 1 -not 
  -name 'development'
  - This means when it rebuilds, it could overwrite the main site content

  Issue with deploy.yml (lines 30-33):
  - It deploys only ./dist directly to the root
  - This completely overwrites the entire gh-pages branch, destroying the
  /development subdirectory

⏺ Root Cause Analysis

  Problem 1: deploy.yml destroys /development
  - deploy.yml:33 uploads only ./dist to GitHub Pages
  - This completely replaces the entire gh-pages branch, wiping out /development

  Problem 2: deploy-environments.yml may overwrite main site
  - Uses GitHub Pages concurrency group, so both workflows compete
  - The content preservation logic has a gap where it might not properly restore main
   site files

⏺ Solution

  Fix deploy.yml - Make it preserve the /development directory:

  1. Fetch existing gh-pages content
  2. Preserve /development subdirectory
  3. Update main site files only
  4. Deploy the combined content

  Fix deploy-environments.yml - Ensure it properly preserves main site:

  1. More robust content preservation logic
  2. Better error handling for missing gh-pages branch

  Would you like me to implement these fixes to both workflow files?
